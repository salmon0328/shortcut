                  What the map says about this floor

                  Every place and link the map holds, drawn on the floorplan. A place with nothing joined to it is ringed, because nothing can be routed to it. Links to another floor are drawn as a short stub with a label, since their other end is on a different plan — so a staircase with no stub is one that leads nowhere yet.

                  Read a drawing

                  Upload the node-map PDFs. Whatever the map does not already have is read out and listed below for you to check — nothing goes on the map until you approve it, so an unapproved place routes nobody and shows up in no search.

                  Lines the drawing did not settle 0

                  Read but not offered: an end touching no place, or a time the surveyor left as ?s. Guessing at these is how a map grows a staircase nobody walked, so they are only reported.

                    Waiting for you 0

                    Correct anything that is wrong, then approve it. Approving puts it straight onto the live map (and into Pending, awaiting the same manual graduation as anything added by hand). Rejecting deletes it — it was never live, so there is nothing to undo.

                    Not yet in the survey 0

                    Everything changed since campus_graph.json was last updated. Surveyed work belongs in that file, where it is version controlled; conditions from reports stay here, because they describe now rather than the building.

                    Moving these into the survey

                    Done from a terminal, not this screen, so that a change to a version controlled file is reviewed as a diff before it is kept. 

                    python scripts/graduate_overrides.py
python scripts/graduate_overrides.py --write
git diff data/campus_graph.json

                    The first command only reports. The second rewrites the survey and takes the graduated entries out of the overrides file, leaving live conditions alone.
